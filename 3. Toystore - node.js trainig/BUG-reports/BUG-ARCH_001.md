# ARCH-001: Дублирование справочников через отдельный эндпоинт

## Описание

При реализации отображения `payment_method.description` в заказе было принято 
решение создать отдельный эндпоинт `GET /api/payment-methods` вместо того, 
чтобы добавить `description` в существующий JOIN в модели заказов.

## Последствия

- Фронт делает 2 запроса вместо 1
- Дополнительная логика сопоставления на фронте
- Лишняя нагрузка на БД

## Правильное решение

Добавить `pm.description as payment_method_description` в SELECT модели 
`getUserOrders`, так как JOIN с `payment_methods` уже есть.

## Вывод

Отдельный эндпоинт нужен только для случаев, когда справочник запрашивается 
независимо от основной сущности
