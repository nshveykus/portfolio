SQL-тренажер: База данных интернет-магазина

> **Учебный проект для изучения SQL, DBeaver и проектирования реляционных баз данных.**

---

## Описание проекта

Этот проект создан для отработки навыков написания SQL-запросов на примере реальной бизнес-логики интернет-магазина. 

В рамках проекта я:
- Спроектировал схему базы данных (10 таблиц) с учетом связей, внешних ключей и нормализации.
- Наполнил MYSQL базу мок-данными (пользователи, товары, заказы, отзывы).
- Отработал 15+ типовых задач тестировщика и аналитика: от поиска дубликатов до оконных функций и CTE.

## Структура базы данных
В MySQL схемы (Schema) и базы данных (Database) — это одно и то же. Поэтому я создал отдельную базу `toystore`  
База `toystore` состоит из следующих таблиц:

- **`users`** — пользователи (email, хеш пароля, ФИО, дата регистрации, флаг бана).
- **`categories`** — категории товаров (поддерживается древовидная структура `parent_id`).
- **`products`** — товары (цена, остаток на складе, привязка к категории).
- **`orders`** — заказы (пользователь, статус, способ оплаты, итоговая сумма).
- **`order_items`** — состав заказа (товары, количество, цена на момент покупки).
- **`payment_methods`** и **`order_statuses`** — справочники.
- **`reviews`** — отзывы пользователей на товары.
- **`carts`** — корзина (поддерживаются авторизованные и гостевые сессии).  

Дополнено:  
- **`refresh_tokens`** — таблица для хранения токенов
- **`daily_sales_summary`** - автоматически обновляемая раз в день таблица для пересчета статистики

##  Примеры выполненных задач (Чек-лист)

| № | Запрос | Навык |
| :--- | :--- | :--- |
| 1 | Поиск дубликатов по email | `GROUP BY`, `HAVING` |
| 2 | Поиск заказов-сирот (без пользователей) | `LEFT JOIN`, проверка на `NULL` |
| 3 | Топ-5 популярных товаров | `JOIN`, `SUM`, `ORDER BY`, `LIMIT` |
| 4 | Процент отменённых заказов | `SUM(CASE WHEN...)` |
| 5 | Пагинация (2-я страница заказов) | `LIMIT`, `OFFSET` |
| 6 | Номер заказа по счету у пользователя | `ROW_NUMBER() OVER(PARTITION BY ...)` |
| 7 | Подсчет «лояльных» клиентов (>1 заказ) | `CTE (WITH ... AS)`, вложенные агрегации |

Полный список запросов можно посмотреть в папке `/queries`.

## Автоматизация обновления витрины

- Создана хранимая процедура refresh_daily_sales_summary для пересчета ежедневной статистики.

- Настроено расписание (EVENT) для автоматического обновления каждый день в 2:00.

- Это гарантирует актуальность данных в дашбордах без ручного вмешательства.

##  Работа с бэкапами и восстановление


###  Стратегия бэкапа

*    `mysqldump` — создается логический дамп базы данных `online_store`.
*    Ежедневно, в 2:00 ночи (через Планировщик задач Windows).
*   Ротация: Автоматическое удаление бэкапов старше 7 дней для экономии дискового пространства.
*   Восстановление: до чистого состояния: `DROP DATABASE` → `CREATE DATABASE` → `mysql < backup.sql`. Чтобы не было временных или тестовых таблиц.

###  Безопасность

Пароль от базы данных **не хранится** в коде скриптов.

*   Для аутентификации используется файл конфигурации `.my.cnf` с ограниченными правами доступа.
*   Для резервного копирования создан отдельный пользователь `backup_user`, которому выданы **минимально необходимые привилегии** (`SELECT`, `SHOW VIEW`, `LOCK TABLES`).

###  Нагрузочное тестирование и отладка

В ходе работы с большими объемами данных (генерация 1 млн+ строк) отработал навыки мониторинга производительности:

*   Использование `SHOW FULL PROCESSLIST` для обнаружения долгих (висящих) запросов.
*   Применение `KILL <id>` для прерывания проблемных запросов без перезапуска сервера.
*   Анализ планов выполнения запросов через `EXPLAIN` для проверки эффективности индексов.
