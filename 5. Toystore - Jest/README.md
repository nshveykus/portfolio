# Toystore - Jest
Покрытие юнит-тестами на Jest моего учебного проекта REST API на Node.js + Express + MySQL.   
Внешние зависимости (БД, bcrypt, Redis) замоканы — тесты быстрые и не требуют поднятой инфраструктуры.

### Запуск

```bash
npm test                  # прогнать тесты с отчётом покрытия
```

### Что покрыто

**Модель заказов (`orders.model.js`) — 100%:**
- Получение заказов пользователя с товарами, статусами, способом оплаты.
- Создание заказа в транзакции: проверка остатков (`FOR UPDATE`), 
  вставка в `orders` и `order_items`, списание остатков, очистка корзины.
- Откат транзакции при любой ошибке внутри `try` (проверено через 
  `mockRejectedValueOnce`).

**Контроллеры (`orders.controller.js`, `user.controller.js`):**
- Хэппи-пути (201 при создании, 200 при обновлении).
- Валидация входных данных (400).
- Маппинг ошибок модели в HTTP-статусы: «Корзина пуста» → 400, 
  «Недостаточно товара» → 400, всё остальное → 500.

**Модель пользователя (`user.model.js`):**
- Создание пользователя с хешированием пароля.
- Подстановка `null` для необязательных полей (`phone`, `birth_date`).
- Обновление профиля с белым списком полей.

### Что сознательно не покрыто

- **Модели и контроллеры**: товаров, отзывов, корзины. Я сосредоточился на самых чувствительных местах
- **Геттеры без бизнес-логики** (`getUserOrders` в части чтения, `findById`)
- **`db.js`**: инициализация пула соединений, не содержит логики.

### Инструменты и приёмы

- `jest.mock()` для подмены модулей (`db`, `bcryptjs`, `redis.service`).
- `mockResolvedValue` / `mockResolvedValueOnce` / `mockRejectedValueOnce` 
  для управления последовательностью ответов.
- `jest.spyOn()` для подмены отдельных методов класса (`UserModel.findById`) 
  с последующим `mockRestore()`.
- `jest.clearAllMocks()` в `beforeEach` для изоляции тестов.
- Моки `console.error` / `console.log`, чтобы не засорять вывод.


## Что я изучил в этом проекте

- **Мокирование модулей** через `jest.mock()` — почему форма мока должна 
  точно повторять форму реального объекта.
- **Особенности `mysql2`**: `pool.execute` всегда возвращает `[rows, fields]`, 
  причём для `SELECT` `rows` — массив, для `INSERT`/`UPDATE`/`DELETE` — 
  объект. 
- **Тестирование транзакций**: как через `mockRejectedValueOnce` заставить 
  код уйти в `catch` и проверить, что был вызван `rollback`, а `commit` — нет.
